## 해석 (결정과 이유)

1. **판정 정확도는 같다.** 정답이 있는 8건을 두 모델 모두 맞혔다. INC-c551a084처럼 탐지 룰 이름이 공격을 가리켜도
   원본을 확인해 오탐으로 판정했다(종료 관문과 원칙 9가 함께 동작).
2. **결정적인 차이는 근거 인용이다.** sonnet은 증거로 적은 원본 위치가 모두 도구 결과로 확인됐고(9/9), haiku는 판정은
   맞아도 9건 중 8건에서 확인되지 않은 위치를 인용했다. 조사 보고서는 사람이 원본을 따라가 검증할 수 있어야 하므로 haiku
   보고서는 그대로 쓰기 어렵다. 이 차이는 매핑으로 이어진다 — 근거가 확인되지 않은 증거는 매핑에서 빠져 haiku 결과는 7건이
   `partial`, sonnet 결과는 전부 `mapped`였다.
3. **심각도 구분.** haiku는 공격이면 거의 전부 CRITICAL로 매겼다. sonnet은 실패하거나 거부된 시도(실습의 `sudo` 거부 등)는
   HIGH, 계정 생성·UID 0처럼 지속성이 생긴 사건만 CRITICAL로 구분했다. 경보가 모두 CRITICAL이면 우선순위를 정할 수 없다.
4. **조사 깊이.** sonnet이 도구를 평균 4.1번(haiku 2.7번) 써서 원본을 더 확인했다. INC-c551a084에서 sonnet은 요청 시각과
   서버 명령 시각을 비교하고, 근처의 관련 없는 대화형 세션(tty)은 근거에서 뺐다.
5. **시간은 같고 비용은 약 3.4배.** 사건당 시간은 거의 같고 LLM 응답은 sonnet이 오히려 빠르다. sonnet은 원본을 더 많이 읽어
   입력 토큰이 약 3배이고, 출력 토큰은 haiku보다 적다. 사건 시간의 상당 부분은 audit 로그 조회(1번에 약 55초)다.

**결정:** 조사 에이전트는 `claude-sonnet-5-5`. 운영 예산은 "하루 조사 사건 수 × 약 $0.56"으로 잡는다.
매핑은 haiku로 두되, 품질은 아래 한계처럼 따로 확인이 필요하다.

## 한계

- **반복 없음:** 모델당 1회라 같은 사건을 다시 돌렸을 때 판정이 흔들리는지는 모른다.
- **오탐 사건이 1건뿐:** 대부분 실제 공격이라 오탐을 가려내는 능력은 충분히 검증되지 않았다.
- **심각도 정답 없음:** 심각도 비교는 사람이 보고 판단한 것이다.
- **매핑 품질 미검증:** 매핑은 haiku로 고정했고 기대 기법을 적지 않아 정확도를 계산하지 않았다. haiku 매핑 결과에는 실제
  행동과 맞지 않는 기법(정리 단계 사건에 무차별 대입 T1110 등)이 섞여 있었다.
- **비용 범위:** 표의 비용은 입력·출력 토큰 기준이고 캐시·매핑 비용은 빠져 있다. 실제 청구액은 콘솔로 확인한다.
- **`/tmp` 실행 사건(INC-3d9dfe95):** 두 모델 판정이 갈렸다(haiku 위협/CRITICAL, sonnet 오탐/LOW). 실제 무엇이었는지 확인하면
  정답표에 추가한다.

## 남은 과제

1. **GPT 비교:** OpenAI API 키가 정해지면 GPT 클라이언트를 추가하고, 같은 9건으로 GPT mini·GPT 상위 모델을 돌려 이 표에 이어 붙인다.
2. **(선택) 반복 측정:** 최종 후보 1~2개만 2회 더 돌려 판정 흔들림을 확인한다.
3. **매핑 품질:** 공격 사건에 기대 기법(`expected_techniques`)을 적고, 고정한 조사 결과(sonnet run1)로 매핑 모델을 비교한다.
4. **(나중에) audit 조회 속도:** 조회 구간이 끝난 뒤 기록만 담긴 교체 파일은 건너뛰어 사건당 30초~1분을 줄인다.
5. **(나중에) sonnet 입력 토큰:** 도구 결과를 많이 읽어 입력 토큰이 크다(사건당 평균 약 20만). 프롬프트 캐시 적중률과 도구 결과
   크기를 점검하면 비용을 줄일 여지가 있다.
