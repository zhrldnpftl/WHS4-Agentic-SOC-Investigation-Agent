### 해석

1. **claude-sonnet-5-5가 가장 정확하다.** 근거 인용이 유일하게 9/9이고, 실패하거나 거부된 시도(실습의 `sudo` 거부·정리)는

3. **gpt-5.5는 정확하지만 비싸다.** 판정 8/8, 근거 8/9, 도구를 가장 많이 썼다(오탐 사건은 7번 조회). 심각도를 높게

4. **claude-haiku-4-5는 판정은 맞지만 근거가 부정확하다(1/9).** 공격이면 거의 전부 CRITICAL로 매긴다. 근거가 확인되지

   종료 관문이 "탐지 근거 원본을 도구로 확인하라"고 연속 거부해도(INC-0977ed78은 5번) 따르지 않았다.
6. **`/tmp` 실행 사건(정답 모름):** 꼼꼼한 세 모델(sonnet, gpt-5.5, Gemini)이 모두 오탐/LOW로 판정해 정상 실행이었을
   가능성이 크다.

### 해석

1. **찾는 정답 기법 수는 5개 모델이 같다(10~11 / 18).** 놓친 기법도 같다(T1505.003 4건, T1098·T1033·T1595.003 각 1건).
2. **5개 모델이 공통으로 붙인 추가 기법은 실제로 맞는 기법이다.** T1105(도구 반입), T1070.004(파일 삭제),
   T1548.003(sudo), T1033(사용자 확인)은 웹셸 실습 흐름의 다른 단계 기법이다. 조사 에이전트가 프로세스 계보를 따라 흐름
   전체의 증거를 모으므로 매핑도 흐름 전체 기법을 붙였다. 정답을 공격 흐름 기준으로 넓히면 5개 모델의 겹침이 모두 오른다.
3. **완전 일치 0/7은 5개 모델 모두 웹셸 사건에 T1505.003을 붙이지 않기 때문이다.** 이 사건들의 증거는 "웹 서버 프로세스가
   명령을 실행했다"는 audit 기록이라 웹셸 파일·요청 자체는 증거에 없다. 매핑이 증거에 있는 행동만 기법으로 바꾸므로
   모델이 아니라 매핑 구조 문제다 — **매핑 팀 판단 필요**. T1098·T1595.003은 하위·유사 기법(T1098.007, T1595.001)을 붙인
   것으로 보이며, 지금 비교는 같은 ID만 맞힌 것으로 친다.
4. **경량 모델만 근거가 약한 기법을 붙였다.** T1560.001(압축 도구로 데이터 묶기 — 실습 중 압축 도구 버전 확인을 오해한
   것으로 추정, haiku·Gemini·gpt-mini), T1003.008(`/etc/passwd`·`shadow`로 계정 정보 탈취 — haiku·Gemini),
   T1548.004(macOS 권한 상승 — 리눅스 서버라 명백히 틀림, gpt-mini). 상위 모델(sonnet-5-5, gpt-5.5)의 추가 기법은 공격
   흐름에 맞는 것과 T1098.007 1건뿐이다.
5. **그래서 상위 모델이 더 정확하다.** 찾는 정답 수는 같지만 매핑 결과는 최종 보고서에 그대로 실리므로, 틀린 기법이
   섞이지 않는 상위 모델이 보고서 신뢰도에 유리하다. 매핑은 사건당 LLM 호출이 적어 상위 모델을 써도 조사 에이전트
   비용보다 훨씬 작다(매핑 단독 실행은 토큰을 기록하지 않아 정확한 금액은 콘솔로 확인).
6. Gemini 무료 티어는 매핑 중 요청 한도(429)에 걸렸으나 재시도로 끝까지 완료했다.

- 비용은 입력·출력 토큰 기준 추정이고 캐시 비용은 빠졌다. 매핑 단독 실행(`run_eval.sh mapping`)은 토큰을 기록하지 않는다.

## 테스트 중 확인된 것

- **종료 관문 약점:** 모델이 관문 거부를 연속으로 무시하면, 거부 횟수 한도 뒤 마무리 턴에서 원본을 확인하지 않은 판정이
  나올 수 있다(gpt-5.4-mini). 보완안: 도구를 한 번도 안 썼으면 마무리 턴 전에 코드가 관련 도구를 직접 조회.
- **EC2 메모리:** 3.7GB에 스왑이 없어, 조사 도구가 audit 로그(스냅샷 240MB)를 통째로 이벤트로 바꿀 때 대시보드 개발
  서버와 겹치면 서버가 굳었다. 테스트 동안 대시보드 개발 서버를 잠시 끄고 4GB 임시 스왑을 쓴 뒤 삭제했다.
  조사 도구가 고른 파일 전체를 읽는 구조라, 운영(자동 실행) 전에 읽는 양 상한과 구간 밖 교체 파일 건너뛰기가 필요하다.
